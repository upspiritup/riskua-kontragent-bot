# Рішення і залежності

Тут записано, що вирішили і чому. Нова залежність або зміна цифри в `pyproject.toml` —
новий рядок із датою (правила, розділи 9 і 10).

## 14.11.2026 — завдання 1.1: каркас і перевірки

- Нова версія живе в пакеті `riskua/` поруч зі старим `app/` у тому самому репозиторії.
  Старий бот працює на Cloud Run, доки новий не покаже той самий звіт із власної бази.
  Якщо згодом захочеться окремого репозиторію, досить перенести `riskua/`, `scripts/`,
  `tests/` (без `legacy/`), `docs/`, `deploy/`, `pyproject.toml` і `CLAUDE.md`.
- Тести старого бота переїхали в `tests/legacy/` без змін у коді: так нові тести дзеркалять
  `riskua/` (`tests/domain/...`), а завдання 1.12 видаляє старе однією папкою.
- Шари, межі й тексти перевіряють власні скрипти в `scripts/` на `ast`, без import-linter:
  правила специфічні (власники бібліотек, «єдине місце» для оточення й часу, кирилиця
  в `domain/`), а повідомлення одразу називають порушене правило.
- Змінні середовища нової версії мають префікс `RISKUA_`, щоб не конфліктувати зі старим `.env`.
- У `[tool.riskua]` у `pyproject.toml` — цифри, які перевіряє `check.py` (правила, розділи 2, 3,
  7.5, 8, 10). Робочі параметри з розділів 5–7 (мережа, база, звіт) житимуть у коді поруч
  із тим, хто їх використовує (`http/limits.py` тощо); їх збіг із правилами перевіряє
  рецензент (розділ 11).
- Тести `config.py`, `clock.py`, `logs.py` лежать у `tests/core/`.
- Ruff не перевіряє Markdown (у документах приклади коду — частина тексту), а правила
  RUF001–RUF003 вимкнено: вони вважають «схожими на латиницю» звичайні українські літери.
- Нова версія слухає окремий тестовий бот (`RISKUA_BOT_TOKEN`): старий бот на Cloud Run
  працює через long polling, а два процеси з одним токеном заважають один одному.
- База в Docker — PostgreSQL 17, порт відкритий лише для `127.0.0.1`.
- GitHub Actions запускає `python scripts/check.py --all` на кожен push у `main` і на кожен
  pull request: перевірка, яку треба пам'ятати запустити, рано чи пізно пропускається.

### Залежності

| Пакет | Навіщо | Чому не вистачило наявних |
| --- | --- | --- |
| `aiogram` 3 | Telegram-бот | вибрано в архітектурі; старий бот на ньому ж |
| `psycopg[binary]` 3 | PostgreSQL: параметри, транзакції, згодом `COPY` | вибрано в архітектурі; бінарна збірка не потребує компілятора в Windows |
| `python-dotenv` | читання `.env` під час локального запуску | був у старому боті; власний розбір `.env` — зайвий код |
| `tzdata` | часовий пояс Europe/Kyiv | у Windows немає системної бази часових поясів |

Інструменти розробки (`pip install -e ".[dev]"`): `pytest`, `pytest-cov` (покриття), `ruff`
(стиль і частина правил), `mypy` (типи: правило про `type: ignore` передбачає перевірку типів).
Версії `ruff` і `mypy` закріплені точно: нова версія може додати перевірки й зламати
`check.py` без жодних змін у коді. Оновлення — окремий коміт.

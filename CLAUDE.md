# RiskUA — інструкції для Claude Code

Telegram-бот для швидкої перевірки українського контрагента за ЄДРПОУ. Нова версія (`riskua/`)
завантажує офіційні відкриті набори в PostgreSQL за розкладом, а перевірка — це запит до власної
бази. Звіт описує ознаки ризику і не робить висновків про людей чи компанію.

Перед роботою прочитай:

- `docs/project-rules.md` — як писати код: шари, межі розміру, тести, мережа, завдання;
- `docs/architecture-v2.md` — архітектура, джерела даних і таблиця завдань (0.1 … 1.12);
- `docs/decisions.md` — ухвалені рішення і залежності з причинами.

## Команда «готово»

```text
python scripts/check.py          # без бази даних
python scripts/check.py --all    # плюс тести з PostgreSQL
```

Завдання готове лише тоді, коли команда зелена. У звіті про роботу наводь її вивід, а не слова.
Усі цифри правил — у `[tool.riskua]` у `pyproject.toml`.

## Як вести завдання

1. Одне завдання з таблиці в `docs/architecture-v2.md` — одна сесія — один набір змін.
2. Спершу план і перелік файлів, потім код.
3. У `riskua/` — до 400 доданих рядків і до 10 змінених файлів (тести не рахуються). Більше —
   поділи завдання і скажи про це.
4. Перевірка не проходить — виправ код. Не змінюй цифри в `pyproject.toml`, не додавай `noqa`,
   `type: ignore` і винятків, щоб перевірка пройшла: зупинись і поясни, що заважає.
5. Нова залежність — рядок у `docs/decisions.md`: навіщо і чому не вистачило наявних.
6. Назви файлів, функцій і змінних — англійською; docstring і коментарі — українською.

## Де що лежить

- `riskua/` — нова версія; `scripts/` — перевірки; `docs/` — документи; `deploy/` — образ Docker.
- Старий бот: `app/`, `main.py`, `Dockerfile`, `requirements.txt`, `tests/legacy/`. Він працює
  на Cloud Run, доки нова версія не покаже той самий звіт. Не змінюй його, крім завдань
  перенесення (правило переноситься разом із джерелом даних і тестами) і завдання 1.12.
- Тести нового коду дзеркалять `riskua/`: `riskua/domain/rules/debts.py` →
  `tests/domain/rules/test_debts.py`. Тести `config.py`, `clock.py`, `logs.py` — у `tests/core/`,
  тести скриптів перевірки — у `tests/scripts/`, зразки файлів джерел — у `tests/fixtures/<набір>/`.
- Тест, якому потрібна база, має позначку `@pytest.mark.db` і фікстуру `database_url`
  (окрема схема на тест, `tests/db/conftest.py`). Тест зі справжньою мережею — `@pytest.mark.net`,
  `check.py` його не запускає.
- Змінні середовища нової версії мають префікс `RISKUA_` і читаються лише в `riskua/config.py`.

## Робоче середовище

```text
python -m venv .venv
.venv\Scripts\activate             # Windows; у Linux: source .venv/bin/activate
pip install -e ".[dev]"
```

База для `--all`: `docker compose up -d db`, далі в `.env`
`RISKUA_TEST_DATABASE_URL=postgresql://riskua:<пароль>@localhost:5432/riskua`.
Тести працюють в окремих схемах і прибирають за собою, тож підходить і робоча база.
